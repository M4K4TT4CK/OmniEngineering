# Gold benchmark triage, 2026-10-21 (ARB-065)

First measurement: Arbiter `d57e479` (native packs and shared probes, no
adapters), 24 gold repositories at the SHAs in `tools/fetch_corpus.sh`,
6,086 KLOC, 12,468 findings, 16 rules over budget. Full numbers are in
`2026-10-21-gold-report.json`. Recall is in `2026-10-21-recall-*.md`.

Method: for each rule over budget, findings were sampled at random (seed
fixed) across repositories and read in context. Large rules were also
sorted into buckets by a pattern over the finding's body, and every bucket
was spot-checked by reading code. Counts marked "≈" come from that
bucketing, not from reading every finding. Nothing in a rule pack or probe
was changed.

## Prioritised fixes

wrong on idiomatic code in a widely used framework.

## Below budget, sampled anyway (true positives worth keeping)

- `java.trust-all-certificates` (6): every one is a real all-trusting
  `X509TrustManager`, behind an explicit `disableTrustManager()` switch
  (`java-keycloak:services/.../HttpClientBuilder.java:67`), in tomcat's
  cloud membership provider (`AbstractStreamProvider.java:65`, documented
  "Insecure trust managers"), or in test harnesses. TP about the code, and
  intentional. That is the right thing for a gate to show.
- `go.http-client-no-timeout` (8): `&http.Client{Transport: tr}` in CLI
  tools and the etcd gRPC proxy (`go-etcd:server/etcdmain/grpc_proxy.go:630`).
  TP by the rule's definition; the proxy one is a real, if minor, finding.
- `ruby.command-injection` (16): interpolated backticks in release tooling
  (`ruby-rubygems:tool/release.rb:588`, `ruby-rails:tools/releaser/lib/releaser.rb:324`).
  TP shape on maintainer-only scripts. Low risk, correct report.
- `typescript.shell-command-built` (7): FP in
  `ts-otel-js:scripts/create-or-update-release-pr.mjs:61`, where `exec` is a
  local wrapper around `execFileSync` (no shell). The rule should resolve a
  locally defined `exec`.
- `go.worker-loop-no-stop` (9): TP shape. These are goroutines in CLI and
  benchmark tools that live as long as the process
  (`go-etcd:tools/benchmark/cmd/put.go:126`).

## Recall (OWASP Benchmark)

Java v1.2 (2,740 cases): in-scope recall 0.045, with a false-positive rate
of 0.043.
- **command injection, 0/126**: the rule matches only the chained
  `Runtime.getRuntime().exec(x)` and `new ProcessBuilder("sh","-c",x)`. The
  benchmark writes `Runtime r = Runtime.getRuntime(); r.exec(cmd + bar)`, and
  builds a `List` that it passes to `pb.command(argList)`.
- **weak randomness, 0/218**: it uses `new java.util.Random()`, which is a
  `scoped_type_identifier` and does not match `type_identifier`, and
  `Math.random()`. The `requires_file` needs a `new Random`. The value goes
  to `rememberMeKey`, and `key` alone is not in the secret-name list.
- **SQL injection, 28/272 with 27 FP**: the `String sql = ...` declaration
  and the sink must be siblings in one block. The benchmark puts the sink
  inside `try { }`.

Python v0.1 (1,230 cases): in-scope recall 0.221, with a false-positive rate of 0.132 (overall 0.111).
- SQL injection 5/5.
- deserialization 18/18 (FPR 0.33).
- code injection 20/20, but every safe case is flagged too (FPR 1.0).
- command injection 7/13 (FPR 1.0).
- weak randomness 0/99: the value is named `value` for a `rememberMe`
  cookie, and `random.normalvariate` is not in the call list.
- weak hash 0/71: no password in the statement.

The safe cases are constant-propagation decoys: a map or `if` makes the
spliced value a constant. A syntactic rule cannot separate them, so these
false-positive rates are a ceiling for this rule design.
