# OmniEngineering Trademark And Identity Policy

This policy protects the project identity while keeping the code, docs,
templates, diagrams, and workspace structure broadly reusable under the Apache
License, Version 2.0.

This is a project policy, not legal advice.

## Protected Project Identity

The protected project identity includes:

- `OmniEngineering`
- `OmniContext`
- OmniEngineering logos, marks, banners, and visual identity assets
- Confusingly similar names or marks used to present a fork, derivative,
  package, hosted service, marketplace listing, extension, or distribution as
  the original project

## Allowed Uses

You may:

- Use OmniEngineering privately, commercially, internally, academically, or in
  public projects.
- Fork and modify the source under the Apache License, Version 2.0.
- Say that your project is "built with OmniEngineering," "based on
  OmniEngineering," or "compatible with OmniEngineering."
- Include attribution required by `LICENSE` and `NOTICE`.
- Use the OmniEngineering name in factual references, documentation, package
  metadata, compatibility notes, academic discussion, or contribution history.

## Uses That Need Permission

You need written permission from the project owner before you:

- Use OmniEngineering or OmniContext as the primary name of a modified fork,
  competing distribution, hosted service, plugin marketplace package, commercial
  product, training product, or consulting package.
- Use project logos, marks, banners, or trade dress as the main identity for a
  modified or independently distributed product.
- Register domains, social handles, package names, trademarks, app listings, or
  organization names that imply official project ownership or endorsement.
- Present modified behavior as the official OmniEngineering release.

## Fork Naming

Forks are welcome. If you distribute a modified fork, use a distinct name and
make the relationship clear.

Good examples:

- `Acme Engineering Workspace, based on OmniEngineering`
- `OmniEngineering-compatible workflow pack for Acme`
- `Fork of OmniEngineering with Acme-specific rules`

Avoid examples:

- `OmniEngineering Pro`
- `Official OmniEngineering Cloud`
- `OmniContext Enterprise`
- Any name or branding that makes users think the fork is the original project
  or officially endorsed.

## No False Endorsement

Do not state or imply that the project owner endorses, sponsors, maintains,
certifies, audits, supports, or warranties your fork, service, product, or
training material unless that relationship is documented in writing.

## Attribution

When distributing a fork or derivative, keep the `LICENSE` and `NOTICE` files
required by Apache-2.0. If you make substantial changes, clearly describe those
changes in your fork's documentation.

## Upstream Contributions

You are not required to contribute changes back. You are strongly encouraged to
return generally useful improvements, bug fixes, diagrams, playbooks, checks,
templates, and compatibility notes to the main project so the wider engineering
community benefits.
