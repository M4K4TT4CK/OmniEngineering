# Maintenance Impact Checklist

Use this checklist before implementing or approving maintenance work.

## Classification

- Maintenance category is identified: corrective, adaptive, perfective, or
  preventive.
- Requirement ID is confirmed.
- Current behavior is understood.

## Impact

- Affected users or systems are identified.
- Affected APIs, schemas, events, files, or interfaces are identified.
- Data migration or compatibility concerns are identified.
- Operational and deployment impact is identified.
- Documentation impact is identified.

## Risk

- Regression risk is assessed.
- Test gaps are identified.
- Rollback or recovery approach is known when needed.
- Dependency or platform risk is identified.
- Security or privacy impact is considered.

## Execution

- Change scope is bounded.
- Existing behavior is preserved unless intentionally changed.
- Regression evidence is planned for bug fixes.
- Deprecation or migration path exists for removals or breaking changes.
